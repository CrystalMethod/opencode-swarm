# SBOM lockfile parsers are truthful against a fixture matrix

## What

`sbom_generate` now emits correct, deduplicated component sets for yarn classic, Yarn Berry, npm v2/v3 (scoped and nested entries) plus npm v1 top-level entries, pnpm v5-v9, and NuGet v1 lockfiles. Previously the parsers silently dropped a third or more of real-world lockfile entries while the tool still reported `pass`: yarn classic lost every range-keyed, quoted-scoped, and comma multi-key entry (only exact-pinned unscoped keys parsed); Yarn Berry lockfiles contributed zero components; npm v2/v3 lockfiles emptied scoped names (`@types/node`) and emitted garbage for nested entries (`debug/node_modules/ms`); pnpm v9+ lockfiles contributed zero components and pnpm 5.x slash-form keys (`/name/version:`) were dropped or mangled; and NuGet v1 `dependencies`-only lockfiles hit a dead fallback arm. Within the npm family, the emitted BOM duplicated manifest-vs-lockfile entries at different versions (`express@4.18.0` alongside the resolved `express@4.18.2`); dedup precedence applies to the npm-family lockfiles (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`) that this issue scoped, and the precedence predicate is ecosystem-qualified so a same-named package from another ecosystem is never suppressed.

Lockfile-resolved entries now take precedence over manifest declared-range entries, exact-purl duplicates collapse, and the tool verdict's fallback branch is honest (`skip` when nothing could be read, matching the declared type). Berry aliases (`alias@npm:real@range`) are recorded under the real package identity, and local/non-registry protocols (`workspace:`, `patch:`, `portal:`, `link:`, `file:`, git, tarball URLs) are excluded from the component set. Truthfulness is pinned by a checked-in hand-authored synthetic fixture matrix (`tests/unit/sbom/fixtures/lockfiles/` — shapes mirrored from real generator output; URLs and hashes are placeholders) whose tests assert exact `name@version` set equality per format — any parser that drops or double-counts a component class now fails the suite instead of passing silently.

## Why

Frontier-audit findings `MICRO-t1-src-sbom-1-1` and `MICRO-t1-src-sbom-1-2` (both HIGH, dual-arm executed against shipped source and real lockfiles): the parsers are the product output of a default-on gate tool and were silently wrong for the second-largest JS package manager's default lockfile shapes, guarded by a 57-test suite whose own fixtures contained the dropped shapes without asserting them (issue #2956, Workstream J PR slot 10).

# Epic Mode catch-up: config opt-in enforced, v2 declared scopes, phase readiness gate, safer Rule 2 commits

## What changed

- **Config opt-in is now enforced (behavior change).** `turbo.epic.mode.enabled` (default `false`) was documented as Epic Mode's master gate but was never read. It is now checked by `/swarm epic on`, `/swarm turbo epic on`, `epic_decide_phase`, `epic_plan_waves`, and `epic_record_divergence` (which return reason `epic-disabled-by-config` with remediation), and by the project-scoped Epic probe that drives Rule 2 auto-commits and the Epic branches of `phase_complete`. `turbo.epic.cochange.enabled` now actually gates the git co-change signal: when off, `p` is computed from declared-path conflicts only and the decision rationale records `cochangeSignal: 'disabled-by-config'` — including `/swarm coupling`, which is no longer independent of that key. The single source of truth is `src/turbo/epic/config-gate.ts`.
- **Epic reads declared scopes only from v2 bindings.** `epic_decide_phase`, `epic_plan_waves`, `/swarm epic decide`, and `/swarm coupling` read declared scope only from live `declare_scope` bindings pinned to the exact plan identity (bindings live 1 h; a plan revision voids them); stale legacy `.swarm/scopes/scope-<taskId>.json` files are ignored. Epic resolves these scopes itself and passes them explicitly to the shared partition planner. `scopes-missing` messages now explain the three causes (undeclared, expired, plan revised). `epic_record_divergence` uses a separate historical, calibration-only reader (`readLatestEpicDeclaredScopeForCalibration` in `src/turbo/epic/declared-scopes.ts`) so calibration still sees the declared baseline after a binding has expired or the plan advanced a phase.
- **`epic_record_divergence` no longer records false "clean" tasks.** Foreground coder writes are attributed to the coder's own session, which the tool previously never read, so every record came out clean with zero actual files. The tool now unions the task's modified files across the architect session and every same-project agent session (read-only). When no attribution exists anywhere it returns `attribution-unavailable` and writes nothing, so calibration never learns from absent data. A declared directory now covers the files written beneath it (segment-aware), so those writes are no longer counted as undeclared. Records carry the plan id and are idempotent per `(planId, taskId)`: a retried call with identical declared/actual sets appends nothing (`already-recorded`), a rework after `NEEDS_REVISION` supersedes the earlier attempt, and calibration applies only the latest record per task in each batch.
- **New `epic_phase_review` tool and `epic_phase_readiness` gate.** While Epic Mode is active for the project, `phase_complete` requires an APPROVED read-only phase reviewer and, after it, an APPROVED phase critic — both dispatched by `epic_phase_review` itself and recorded to `.swarm/evidence/{phase}/epic-phase-review.json`, bound to the plan and to every phase task's evidence (24 h TTL). Block codes: `EPIC_PHASE_REVIEW_MISSING`, `EPIC_PHASE_REVIEW_INVALID`, `EPIC_PHASE_REVIEWER_NOT_APPROVED`, `EPIC_PHASE_CRITIC_MISSING`, `EPIC_PHASE_CRITIC_NOT_APPROVED`, `EPIC_PHASE_REVIEW_STALE`, `EPIC_PHASE_PLAN_UNREADABLE`. Under Epic it replaces Lean Turbo's `lean_turbo_readiness` gate. The gate appears in the `phase_complete` gate report only while Epic is active; without Epic the report is unchanged.
- **`EPIC_MODE_BANNER` is now a seven-step flow** and states that per-task Stage A (`pre_check_batch`) and Stage B (reviewer + test_engineer) are always required under Epic before `update_task_status(completed)` (matching what `update_task_status` enforces at runtime), adds the `epic_phase_review` step, explains scope expiry and `epic-disabled-by-config`, tells the architect to declare scopes at the start of every phase (completing a phase's last task advances the phase, which voids live bindings) and to widen a scope with `replace_existing: true`, and no longer mentions the removed `epic_run_phase`. It is no larger than before (≈1,976 vs ≈1,994 estimated tokens). `epic_decide_phase`'s `epic-mode-not-active` result now carries a remediation `message`.
- **Rule 2 per-task commits are scope-exact.** Only the task's declared-scope files are staged — matched as literal pathspecs, so a scope entry such as `app/[id].tsx` or `src/*.ts` can no longer glob-match sibling work in progress — and the commit is pathspec-restricted (`--only`), so files already staged by the user or a sibling task are no longer swept into a `swarm(task <id>):` commit. With no resolvable scope and a dirty working tree, no marker is written (result `scope-unresolved`) and a critical warning gives the remediation, so Rule 3 never treats uncommitted work as committed. A clean tree still gets an empty marker. A staged `git mv` rename whose destination is in scope now commits the source-path deletion too, instead of leaving it staged.
- **Activation greenfield gate documented as implemented:** it passes on a non-git project (Rule 1) or on predecessor evidence (every cross-phase upstream task has a `swarm(task <id>):` marker; phantom dependency ids fail closed). `min_commits_for_signal` is telemetry only.
- **Dead code removed:** the legacy `epic_run_phase` execution path (`executeEpicRunPhase`) and unused Epic state helpers (`resetEpicSession`, `saveEpicSessionState`).
- The MCP read-only surface's write-tool denylist now also covers `epic_decide_phase` and `epic_phase_review`.

## Why

A catch-up audit found Epic Mode's documented contract and its runtime had drifted: the config gates were inert, planners could trust stale v1 scope files, Rule 2 could commit unrelated staged files or mark uncommitted work as committed, abandoned sessions could keep Epic on for the whole project indefinitely, and nothing reviewed concurrently executed waves as a whole before a phase closed.

## Migration steps

- To keep using Epic Mode, set `turbo.epic.mode.enabled: true` inside a `turbo` block that declares a valid `strategy`, e.g. `{ "turbo": { "strategy": "standard", "epic": { "mode": { "enabled": true } } } }`. A `turbo` block without `strategy` (or `strategy: "lean"` without a `lean` object) fails validation and is dropped whole.
- To keep the co-change signal, also set `turbo.epic.cochange.enabled: true`.
- Under Epic Mode, call `epic_phase_review(phase)` before `phase_complete`.

## Breaking changes

- Projects that used `/swarm epic on` or `/swarm turbo epic on` without `turbo.epic.mode.enabled: true` will now be refused until they opt in.
- `/swarm coupling` and Epic decisions no longer include the co-change signal unless `turbo.epic.cochange.enabled: true`.
- `phase_complete` blocks under Epic Mode until `epic_phase_review` records approving verdicts.

## Known caveats

- Declared scopes expire after 1 h. Long-running phases must re-run `declare_scope` before planning or completing tasks whose bindings have lapsed, or Rule 2 will refuse to write a marker for a dirty tree.

# Epic Mode v2

## What changed

- **Epic completion markers are plan-scoped.** Rule 2's `swarm(task <id>):` marker commit now ends with a `Swarm-Plan: <planKey>` trailer (`planKey = sha256(planIdentityHash + '|' + planEpoch).slice(0, 16)`). Rule 2's idempotency check and Rule 3's predecessor evidence (read by `epic_next_wave`) honor a marker only when it belongs to the current plan — its trailer matches the current plan key, or it is a legacy marker without a trailer committed at/after the plan root (the earliest plan-ledger event). Each read is a single bounded `git log` (marker `--grep`, `--max-count`); the plan-root check runs per commit rather than via `git log --since`, so an older-dated commit (clock skew, rebased history) cannot hide newer markers.
- **Stale worktree merge failures no longer suppress Rule 2.** The shared `.swarm/worktree-merge-status.json` registry is keyed by bare task id and never cleaned. Epic now ignores a failure recorded before the current plan's root; a failure with no timestamp is still treated as relevant (fail closed). `/swarm epic status` lists recorded merge failures as blocking, undated, or stale, with the remedy. New `/swarm epic clear-merge-failure <taskId> [--confirm]` clears a recorded failure that no longer reflects reality (for example an undated record from a cancelled task); without `--confirm` it only previews.

- **Breaking: an epic is now plan-scoped and opened explicitly.** `/swarm epic on` and `/swarm epic off` were removed (they now fall to the usage text). `/swarm epic start [--force]` opens one epic for the current plan; `/swarm epic close [--abandon]` closes it and writes a close report to `.swarm/epic/reports/` and `.swarm/epic-prior/reports/` (newest 50 kept, survives `/swarm close`). `/swarm epic status` shows the epic, detects an epic orphaned by a plan rename/replacement, repairs the `.swarm/epic/epic.json` sentinel, and retires Epic v1 per-session state once.
- **Start refusals.** `/swarm epic start` refuses, in order: `epic-disabled-by-config`, `no-plan` / `plan-ledger-unreadable`, `epic-already-open` (same plan — idempotent) / `epic-open-for-other-plan`, `turbo-active` (config `turbo_mode`, a session with Turbo on, or a running Lean run), `dirty-baseline` (git: uncommitted changes outside `.swarm/`), `in-flight-coders` (any coder dispatch, background delegation, unsettled settlement, or preserved/recovery lane in the project), and `not-epic-sized`.
- **Epic sizing.** A plan is epic-sized when it has at least `turbo.epic.sizing.min_tasks` (6) pending tasks, at least `min_scope_coverage` (0.8) of them carry a scope, and the Amdahl-adjusted speedup of a wave-planner dry run is at least `min_effective_speedup` (1.25, with `coder_fraction` 0.6). Otherwise the start is refused with the reasons and "run it in Balanced"; `--force` overrides and is recorded. Non-git projects run an epic serially (one task per wave), so they always need `--force`.
- **Epic branch (new default) and landing at close.** New `turbo.epic.commit_policy: "epic-branch" | "current-branch"` (default `epic-branch`). In a git project `/swarm epic start` checks out `swarm/epic/<epicKey>` and every Epic commit lands there; it refuses `detached-head` and `epic-branch-exists` (a leftover branch from an abandoned epic of the same plan — delete it with `git branch -D`), and rolls the start back (`branch-create-failed`) if the checkout fails. `/swarm epic close [--land squash|merge|none]` refuses a dirty tree, a missing original branch, and a detached HEAD whose commit would be orphaned before changing anything (an epic branch without changes reports `nothing-to-land`), then lands the branch onto the original branch: `squash` (default) leaves the epic's diff **staged and uncommitted** for you to review and commit, `merge` makes a `--no-ff` merge commit, `none` only switches back. The epic branch is never deleted by the plugin. A landing conflict is rolled back (`git reset --merge` for squash, `git merge --abort` for merge), the epic stays `closing`, and rerunning close resumes; landing is idempotent. `--abandon` and `/swarm close` never land — they switch back to the original branch when the tree is clean and keep (and name) the epic branch.
- **Branch drift is refused.** While an epic-branch epic is open, `epic_next_wave` blocks with `epic-branch-mismatch` (`EPIC_BRANCH_MISMATCH`, remedy `git checkout swarm/epic/<epicKey>`) when HEAD is not the epic branch, and Rule 2 skips its completion marker (with a critical warning) instead of committing onto another branch.
- **Breaking: `epic_next_wave` replaces `epic_decide_phase`, `epic_plan_waves` and `epic_record_divergence`** (all three removed, with `/swarm epic decide` and `/swarm epic last`, the plan-wide `p` activation gate, and `.swarm/evidence/epic-promotions.jsonl`). The architect calls `epic_next_wave` (no arguments, idempotent) and does what its `status` says: `dispatch` (a wave of ready tasks with disjoint declared scopes, plus step-by-step instructions — one `Task` per task id in one message, per-task Stage A/B, then call again), `declare-scopes`, `in-progress`, `blocked` (`task-blocked`, `merge-failed`, `git-failed`, `dirty-baseline`, `predecessor-missing`, `plan-revised`, `task-reopened`, `epic-branch-mismatch` — each with its remedy), `phase-ready-for-review`, `epic-complete`, or `refused`. A wave closes once every task is completed, closed, or removed and none has a merge failure recorded since the wave was issued; phases run strictly in order — phase N+1 starts only after `phase_complete` of phase N (which now records the phase complete on the epic). Predecessors completed before the epic started need no completion marker (their work was in HEAD at start); only the epic's current phase can be recorded complete by `phase_complete`. A closed or removed task's merge failure does not hold its wave, and the shared merge-status registry is trusted only while bound to this project. Global/protected-file tasks and tasks touching calibration-learned hot modules run alone; with `turbo.epic.cochange.enabled`, co-changing tasks go to different waves. The epic record keeps every wave (frozen declared scopes, base and close HEAD) and per-task outcomes (rework generation, Stage A/B failure lower bounds, merge-failure snapshot, reopen count, undeclared files), shown by `/swarm epic status` and the close report. Divergence is computed at wave close from coder-session attribution (git fallback: changes since the wave's base) and still feeds calibration. `epic_phase_review` refuses (`waves-open`) and `phase_complete` blocks (`EPIC_PHASE_WAVES_OPEN`) while a wave of the phase is open. The Epic banner is now short narration: "call `epic_next_wave` and do exactly what its status says"; per-task QA is never waived. `turbo.epic.mode.min_commits_for_signal` is no longer read; `activation_threshold` only bounds the calibration override shown by `/swarm epic calibration`.
- **One project probe drives every Epic behaviour.** Rule 2, the `epic_phase_readiness` gate, the Epic banner, `epic_next_wave` / `epic_phase_review`, and per-task attribution retention all ask "is an epic open for the current plan?". The check is sentinel-first: a project with no open epic pays one `existsSync` — no database open, no config read, no write. The per-session Epic rows, their 24 h TTL and heartbeat, and the session-lifecycle hooks are gone; `/swarm reset-session` no longer touches Epic (an epic outlives a session); `/swarm close` closes an open epic as `abandoned-by-swarm-close` before archiving. While an epic is open the standard parallel-dispatch advisory is suppressed (the Epic banner and `epic_next_wave` own dispatch guidance), and each wave is capped at the epic's width.

## Why

Task ids repeat across plans (every plan has a `1.1`). Before this change, a previous plan's `swarm(task 1.1):` marker made the current plan's 1.1 an idempotent skip — its work was never committed — and falsely satisfied Rule 3 for dependants. A merge failure recorded for a previous plan's `1.1` also suppressed the current plan's Rule 2 marker indefinitely.

## Migration steps

- Architect prompts or automation that call `epic_decide_phase`, `epic_plan_waves` or `epic_record_divergence` must call `epic_next_wave` instead. `/swarm epic decide` / `/swarm epic last` are gone; use `/swarm epic status`.
- Replace `/swarm epic on` with `/swarm epic start` (once per plan) and `/swarm epic off` with `/swarm epic close` (or `/swarm epic close --abandon` with tasks still pending). Legacy Epic v1 per-session state is retired the first time `/swarm epic status` runs; nothing is opened automatically.

- None required. Markers written before this release have no trailer; they still count for the plan in progress if they were committed at/after its plan root. Markers from earlier plans no longer count.
- To commit a task's changes manually as Rule 2 evidence, end the commit message with the `Swarm-Plan: <planKey>` trailer that the `scope-unresolved` warning prints.

## Known caveats

- Epic keeps Turbo off where it can see it: `/swarm epic start` refuses on config `turbo_mode`, a Turbo session in the same process, or a running Lean run; while an epic is open, config no longer seeds Turbo into new sessions, restored sessions come back with Turbo off, and `/swarm turbo` refuses to enable it. Turbo enabled in a different OpenCode process on the same project is not detectable.

- Until the next Epic v2 change, a file a task writes outside its declared scope (including test files the test_engineer writes) is not committed by Rule 2, so the next `epic_next_wave` pauses with `blocked: dirty-baseline` until you commit (or discard) it. Declare each task's test files in its scope to avoid the pause.
- Until the next Epic v2 change (commit at landing), task work is still committed at completion (Rule 2). Reworking a worktree-isolated task after a failed Stage B inside a wave can therefore fail its merge-back (the rework worktree lacks the first attempt's uncommitted landing); `epic_next_wave` then blocks `merge-failed` with the recovery steps.
- Renaming or replacing the plan while an epic is open orphans the epic: Epic behaviour turns off for the new plan, `/swarm epic status` says why, and `/swarm epic close --abandon` closes it.
- With the default `epic-branch` policy, keep the epic branch checked out until the epic closes; switching branches mid-epic stops Epic planning and Rule 2 markers until you switch back. Set `turbo.epic.commit_policy: "current-branch"` to keep the previous behaviour (commits on the branch current at start, nothing landed at close).
- `--land squash` stages the epic's changes without committing them; the `swarm/epic/<epicKey>` branch stays until you delete it, and starting a new epic for the same plan is refused while it exists.

- A plan whose identity cannot be resolved (for example conflicting plan-epoch metadata in the ledger) gets no Rule 2 marker, and Rule 3 fails closed for it (dependants are serialized/demoted) until the ledger is repaired.
- Plan-ledger re-roots: re-rooting the plan ledger — a `save_plan` that renames the plan's title or swarm, `/swarm rollback`, or a truncated-ledger recovery — mints a new plan root and plan key. Markers committed before the re-root are orphaned (Rule 3 no longer counts them, so dependants serialize until re-completed: fail closed), and a worktree merge failure recorded before the re-root is treated as stale, so Rule 2 writes the marker even though that merge never landed (fail open). Check `/swarm epic status` and `/swarm lanes` after such a re-root. The wave advance rule already dates merge failures against the wave's issue time.
